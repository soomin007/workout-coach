# 2026-11-22 세션 로그

## 요약
운동 중 알림 세션의 스크린샷을 본 사용자가 앱 그래픽이 예쁘지 않다고 해서 화면 전체의 그래픽을 개편했다.
지금 화면을 진단하고 Leap, Strong, Hevy, 토스를 참고한 시안 셋을 실제 앱에 덧입혀 비교 페이지로 보였고, 사용자가 A(Leap 다듬기)를 골랐다.
A 를 모든 화면에 적용하고 문장 부호와 어색한 줄바꿈을 줄였으며, 운동 중 알림과 앱 아이콘을 다듬어 새 APK 를 케이블로 깐 뒤 push 했다.

## 결정 사항
- 사용자가 원하는 것을 모른다고 해서 글 대신 그림으로 고르게 했다. 시안 CSS 를 실제 앱에 덧입혀 Playwright 로 찍었고, 폰에서도 넘겨 볼 수 있게
  claude.ai 비교 페이지(지금, A, B, C 를 홈, 운동 중, 카드 아래쪽과 두 테마로)를 만들었다. 사용자는 차이를 잘 모르겠다며 A 를 골랐다.
- 사용자가 꼽은 AI 디자인 흔적은 고정폭 글꼴, 과도한 문장 부호, 요상한 줄바꿈, 획일적인 왼쪽 정렬이다. 다 고치기보다 없어도 되는 것을 덜라는 지시라서,
  문장 부호와 줄바꿈을 덜고 왼쪽 정렬은 목록 화면이라 그대로 두었다(숫자는 이미 칸 가운데에 있다).
- 어두운 테마의 연보라 버튼과 민트 완료 줄은 한 토큰이 글자색과 바탕을 함께 맡은 탓이라, 바탕용 토큰을 따로 두었다(known-issues 55).
  check-design.mjs 는 규칙(버튼 글자 4.5:1)을 그대로 두고 비교 대상만 fill 로 바꿨다.
- 처방 문구는 core 글이라 nw 를 못 쓴다. 줄바꿈은 화면에서 escText 로 붙이고, 문구 자체는 명사로 끊은 조각을 문장으로 바꿨다.
- 알림은 남은 시간이 가장 중요한 정보라 시간을 크게, 상태 말은 옅게 옆에 두었다. 승격이 되는 폰의 기본 모양은 바꾸지 않았다.
  아이콘은 남색 바탕, 파란 덤벨, 민트 체크가 옛 어두운 테마 배색과 같아서 체크를 빼고 강조색 바탕의 흰 덤벨 하나로 했다.
- 알림 캡처는 시험용 앱(Coach 시험)에서 세트를 끝내 띄우고, uiautomator 로 우리 알림 카드의 위치를 찾아 그 부분만 잘라 다른 앱 알림이 찍히지 않게 했다.
  스크립트는 공유 메모 폴더(graphic-directions)에 사본이 있다. 시험용 앱은 확인 뒤 지웠다.
- 파이썬으로 파일을 고치면 LF 가 CRLF 로 바뀐다(저장소에는 .gitattributes 가 LF 로 넣는다). sed 로 되돌렸다. 다음에는 `newline='\n'` 으로 쓴다.

## 이어서: 홈 추천 카드 버튼 줄
사용자가 바뀐 화면의 체감이 크지 않다며 홈 추천 카드만 더 고쳐 달라고 했다.
- `app/js/ui/views.js`, `app/styles.css`: 시작과 부위 직접 선택 버튼은 카드 폭을 반씩 꽉 채운다(`.hero-actions`, 높이 48px).
  그 아래 오늘 헬스장 못 가요, 계산 자세히, PT 기록은 B 시안처럼 테두리 없는 파란 글자 버튼(`.link-btn`)으로 바꿔 한 줄 양끝에 맞춘다(`.hero-links`).
  첫 버튼과 끝 버튼의 바깥 여백을 없애 위 버튼의 양끝과 글자 끝이 맞는다. 켜진 상태(오늘 PT 있어요, 헬스장 휴무 해제)는 주황 글자다.
- 버튼이 넷인 날(오늘 PT 없다고 한 날)은 두 줄에 둘씩 양끝을 맞추고, 320 폭에서는 PT 요일의 세 버튼도 한 줄에 들어가게 글자를 12px 로 줄였다.
  평일, PT 없다고 한 날, PT 요일을 320, 360, 390, 1440 폭에서 재서 위 버튼과 양끝 차이가 모두 0px 인 것을 확인했다.
