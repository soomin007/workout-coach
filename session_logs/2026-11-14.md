## 결정 사항
- 무거운 날 상체 휴식을 180초로 줄였다. 11/12 랫풀다운과 11/14 오버헤드프레스 무거운 날 모두 ✓ 간격 2분 안팎(세트 시간 포함)으로
  톱세트와 백오프를 채웠고, 180초는 무거운 세트에 권하는 3~5분의 아래쪽 끝이다. 하체는 10/1 스쿼트에서 3~6분을 쉬어 240초를 남겼다.
- 카탈로그 기본 휴식은 바꾸지 않았다. 복합 120~180초, 고립 75~90초는 근거 범위 안이고(Singer 2024는 90초를 넘기면 근비대 차이가 없다고 했다),
  11/14 고립 운동은 오히려 앱 값보다 길게 쉬었다(레터럴레이즈 ✓ 간격 189초와 202초). PT 쌤이 본 긴 휴식은 이쪽일 가능성이 있다.
- 이두 자리를 덤벨 컬과 해머컬로 번갈아 돌리지 않았다. 당기기가 주 1회라 번갈아 하면 운동마다 2주에 한 번이 되어 더블 프로그레션이 느려진다.
- 하위 세션의 브랜치는 이미 origin/main 에 들어 있어 병합 없이 main 을 앞으로 당겼다. 보관 전에 두 워크트리에 커밋 안 된 변경과
  node_modules 폴더 연결이 없는 것을 확인했다(연결이 남아 있으면 워크트리를 지울 때 메인 저장소 파일까지 지워질 수 있다).
  보관 뒤 워크트리 두 개는 앱이 새 세션용으로 남겨 두는 재사용 풀이 되었고, 앱이 스스로 다시 쓰거나 지운다.

## 세션 2: 안드로이드 앱과 휴식 끝 알림

### 요약
크롬은 화면이 꺼지면 휴식 타이머 진동을 울리지 못해서, 앱을 Capacitor 로 감싼 안드로이드 앱으로 만들고 첫 네이티브 기능으로
휴식 끝 로컬 알림을 넣었다. 앱은 server.url 로 GitHub Pages 를 띄워 push 만으로 화면이 바뀐다. 사용자 폰(갤럭시 S22+, 안드로이드 16)에
설치해 화면을 끈 채 재 보니 60, 120, 180초 휴식 모두 알림이 0.04초 안에 떴고, Doze 를 강제로 건 60초와
실제 세트 체크 흐름(180초)도 0.05초 안이었다. 단위 테스트 219개, E2E 98개가 통과했다.
사용자가 앱용 GitHub 토큰을 새로 만들어 앱의 동기화를 연결했고, 앱이 받은 기록(세션 31개, 운동 기록 132개)이 data.json 과 같은 것을 확인했다.

### 주요 변경
- `capacitor.config.json`, `android/`, `native/web/`: Capacitor 8.6.0 안드로이드 프로젝트. 매니페스트에 USE_EXACT_ALARM, VIBRATE 를 더했고
  런처 아이콘과 시작 화면을 앱 아이콘(app/icon.svg)으로, 알림 아이콘을 스톱워치 벡터로 바꿨다. offline.html 은 첫 실행에 인터넷이 없을 때 뜬다.
- `app/js/core/restalarm.js`: restTimer 에서 예약할 알림(끝 시각, 키)을 정하는 순수 함수. 시간이 흐르는 것만으로는 키가 바뀌지 않는다.
- `app/js/ui/native.js`: window.Capacitor 브리지로 알림 플러그인을 부른다. 시작 때 채널을 만들고 권한을 묻고, 렌더마다 키가 바뀐 때만 예약하거나 지운다.
- `app/js/main.js`, `app/js/ui/views.js`: renderRest 에서 알림을 맞추고, 알림을 쓸 수 있으면 화면 안 진동을 겹쳐 내지 않는다. 설정 탭에 앱에서만 보이는
  '휴식 끝 알림' 카드(상태, 시험 알림, 정확한 알람 허용)를 더했다. `app/sw.js` SHELL 에 새 파일 두 개를 넣었다.
- `tests/unit/restalarm.test.js`, `tests/unit/sw_shell.test.js`, `tests/e2e/native.spec.js`: 전이 함수를 거친 예약 계획, SHELL 누락 검사,
  브리지를 흉내 낸 예약, 취소, 권한 거부, 크롬 동작 검사.
- `scripts/android.mjs`(빌드, 설치), `scripts/measure-notice.mjs`(adb 와 웹뷰 디버깅 포트로 지연 실측), `docs/NATIVE_APP.md`,
  `docs/REQUIREMENTS_AND_INVARIANTS.md`(결정과 보존 목록), `known-issues.md` 47~50, `.gitattributes`(.bat 은 CRLF, .jar 는 바이너리).
- PC: JDK 21 과 Android SDK 명령줄 도구를 `C:\Users\soomi\Android` 에 압축 파일로 풀었다. 시스템 JAVA_HOME(JDK 17)은 그대로다.

### 결정 사항
- 웹 화면은 APK 에 묶지 않고 server.url 로 받는다(사용자 결정). Capacitor 8.6.0 소스에서 브리지가 addDocumentStartJavaScript 로
  주입되는 것을 확인해, 서비스 워커가 캐시에서 준 화면에도 플러그인이 붙고 오프라인에서도 동작한다고 판단했다.
- @capacitor/core 를 들이지 않고 브리지의 nativePromise 로 부른다. 빌드 없는 ES 모듈 구조를 지키기 위해서다. APK 와 웹 코드의 버전이 어긋날 수 있어
  PluginHeaders 로 플러그인이 있는지 보고 부른다.
- 예약은 동작마다 붙이지 않고 restTimer 를 렌더 뒤에 맞추는 방식으로 했다. 세트 체크, -15/+30, 다음 세트, 건너뛰기, 종료가 한 길로 맞춰지고,
  상태 변경은 전이 함수로만 한다는 원칙도 지킨다.
- 앱이 화면에 떠 있을 때도 알림을 띄운다. 화면 유지를 켠 채 폰을 벤치에 두어도 소리로 알 수 있게 했고, 거슬리면 바꾸기로 남겼다.
- Capacitor 패키지는 나온 지 2주가 지난 8.6.0 으로 고정했다(8.6.1, 8.6.2 는 이틀 전 게시). 뒤로 가기가 앱을 닫지 않게 @capacitor/app 을 들였다.
- android/ 소스는 커밋하고 APK 와 빌드 산출물은 커밋하지 않는다. 디버그 서명 키는 이 PC 의 ~/.android/debug.keystore 다.
- 실측 뒤 시험 세션을 지우는 명령이 12분 멈췄다. 화면을 끈 사이 폰이 잠겨 앱 웹뷰가 디버깅 명령을 처리하지 않았고,
  출력이 파이프에 걸려 시작에서 멈춘 것으로 잘못 알렸다. 측정 스크립트가 앱이 화면 앞에 있는지 먼저 보고 잠금 해제를 청하게 고쳤다(known-issues 50).
- 동기화 토큰은 Claude 가 옮기지 않는다. 비밀 값이 도구와 기록을 거치지 않게 사용자가 앱용 토큰을 새로 만들어 붙여 넣는다.
