# 알림에서 세트 기록하기 제안, 2026-11-21

상태: 채택(2026-11-21, 사용자가 추천대로 고름). 출발점은 11/15 코어 날 세션 메모(처리 장부 키 54a8becfb6b5)다.
구현과 실측은 docs/NATIVE_APP.md 의 '운동 중 알림' 절에 있다. 폰에서 확인해 보니 One UI 잠금 화면은 알림을 접어서 보여 기본 버튼이 숨었다.
그래서 라이브 업데이트를 쓸 수 없는 폰에서는 접힌 줄에 남은 시간과 버튼을 함께 그리도록 더했다(known-issues 53). 버튼 수는 그대로 하나다.

## 문제

사용자는 11/15 코어 날 메모에서 음악 앱처럼 알림 창에서 다음 운동 버튼을 누르고, 남은 휴식 시간도 보고 싶다고 했다.
휴식 끝 알람만으로는 부족하고, 운동하는 동안에는 앱을 열지 않아도 되기를 바란다.

지금 앱은 휴식이 끝나는 순간 알림을 한 번 울린다(11/14). 세트를 기록하려면 잠금을 풀고 앱을 열어 '다음 세트 기록'을 눌러야 하고,
남은 휴식 시간은 앱 화면에서만 보인다. 11/15 코어 날에는 세트가 21개였고, 10종목 가운데 5종목(할로우 홀드, 사이드 플랭크,
스트레칭 셋)이 버티기 운동이라 앱의 버티기 타이머를 썼다.

지켜야 할 제약은 셋이다. 첫째, 폰이 잠겨 있으면 앱 웹뷰가 자바스크립트를 처리하지 않는다(11/14 실측, known-issues 50).
운동 기록은 웹뷰 저장소에 있고 session.js 의 전이 함수로만 바뀌어야 한다. 둘째, 운동 중에 누를 버튼과 메뉴를 늘리지 않는다
(10/18 사용자 지시). 셋째, 웹 코드는 push 하면 바로 바뀌지만 네이티브 코드는 APK 를 다시 깔아야 바뀐다(known-issues 49).

## 원리로 다시 본 진단

잘 된 운동 앱들은 알림을 운동의 리모컨으로 쓴다. 알림 하나가 지금 상태(남은 휴식, 다음 세트)를 보여 주고,
가장 흔한 다음 동작인 '처방대로 했음' 하나를 앱을 열지 않고 하게 한다. 값이 처방과 다를 때(덜 한 반복, 바꾼 무게)는 앱으로 보낸다.
StrongLifts 가 실패 버튼을 하나 더 둔 것은 5x5 처럼 실패가 진행 규칙의 일부인 앱이어서다.

남은 시간은 앱이 매초 알림을 고쳐서 보이는 것이 아니라, 앱이 끝 시각만 넘기면 시스템이 그린다(크로노미터 카운트다운, API 24).
시계 앱의 타이머와 라이브 업데이트 칩이 이 방식이다. 잠긴 동안 웹뷰가 멈추는 우리 앱에 꼭 맞는 성질이라,
앱이 잠들어 있어도 알림의 시간은 맞게 흐른다.

버튼은 앱 화면을 열지 않는 방식이어야 잠금을 풀지 않고 동작한다. 지금 쓰는 @capacitor/local-notifications 8.3.1 은
버튼을 누르면 앱 화면을 여는 방식(PendingIntent.getActivity)이라 잠금 화면에서는 잠금 해제부터 요구하고, 시스템 카운트다운도 지원하지 않는다.
그래서 APK 안에 작은 네이티브 플러그인을 직접 만든다. 버튼은 브로드캐스트로 앱의 리시버를 깨워 앱 화면 없이 처리한다.

잠긴 동안 웹 코드가 돌지 않으므로, 버튼을 누른 사실은 네이티브가 기록장에 적고 앱이 다시 열릴 때 웹 코드가 그 기록을
세트 완료 전이(toggleSetDone)에 누른 시각 그대로 넣는다. 결과는 그 시각에 앱에서 '다음 세트 기록'을 누른 것과 같다.
세트 간격, 휴식 타이머, 코칭 문구, 동기화가 모두 지금 길을 그대로 탄다.

남은 문제는 알림이 다음 세트와 다음 휴식 길이를 미리 알아야 한다는 것이다. 세트를 끝내야 바뀌는 값이 있다
(무거운 날 톱세트 뒤 백오프 무게, 워밍업 뒤의 짧은 휴식). 그래서 웹 코드가 깨어 있을 때 상태 사본에 같은 전이 함수를 차례로 적용해,
남은 세트를 처방대로 했을 때 알림에 보일 순서를 미리 계산해 넘긴다. 네이티브는 계산하지 않고 그 목록을 한 칸씩 넘긴다.
알림 문구도 웹 코드가 만들어 넘기므로 문구를 고칠 때 APK 를 다시 깔 필요가 없다.

## 제안

### 1. 알림 버튼은 '세트 완료' 하나

알림에는 버튼을 하나만 둔다. '세트 완료'를 누르면 알림에 적힌 다음 세트를 처방값 그대로 완료하고 다음 휴식을 시작한다.
앱 하단의 '다음 세트 기록'과 같은 동작이다. 휴식 중에 누르면 휴식을 일찍 끝내고 그 세트를 한 것으로 보므로 알림에 건너뛰기가 따로 필요 없다.
휴식 조절(−15, +30)과 건너뛰기는 앱 화면에 그대로 둔다.

이 버튼은 새로 누를 버튼이 아니라 잠금 해제, 앱 열기, '다음 세트 기록'을 한 번으로 줄이는 자리다. Hevy 처럼 휴식 조절까지 두면 버튼이 넷이 된다.
휴식 끝 알림은 울릴 뿐 운동을 막지 않으므로, 더 쉬고 싶으면 울린 뒤에 누르면 된다. 처방보다 덜 한 세트는 StrongLifts 처럼 앱을 열어 고친다.

다른 선택지는 '+30초'를 더한 버튼 둘이다. 11/14 기록에서 고립 운동은 앱 값보다 길게 쉬는 일이 많았으므로
(레터럴 레이즈 세트 간격 189초, 202초), 알림이 먼저 울리는 것이 거슬리면 이쪽이 낫다.

### 2. 버티기 세트

가장 권하는 방법은 같은 자리의 버튼 이름이 '버티기 시작'으로 바뀌는 것이다. 누르면 앱 안 버티기 타이머와 같은 단계
(준비 5초, 버티기, 좌우 운동이면 자세 바꾸기 10초와 반대쪽)를 알림 카운트다운으로 보이고 단계마다 진동한다.
끝나면 처방 시간으로 세트를 완료하고 휴식을 시작한다. 일시정지와 +5초는 앱에만 둔다. 단계마다 알람을 예약하므로 네이티브 코드가 가장 많이 늘어난다.
그래서 휴식 카운트다운과 세트 완료를 폰에서 확인한 뒤 두 번째 단계로 만든다.

두 번째 방법은 버티기 세트도 '세트 완료'로 처방 시간을 바로 기록하는 것이다. 시간은 사용자가 따로 잰다.
세 번째 방법은 버티기 세트에서는 버튼을 빼고, 알림을 눌러 앱의 타이머를 쓰게 하는 것이다.

### 3. 잠긴 동안 누른 기록

앱이 깨어 있을 때 웹 코드는 렌더마다 알림 계획(남은 세트 순서, 세트마다의 휴식 길이, 알림 문구)을 계산하고,
바뀐 때만 네이티브에 넘긴다. 지금 휴식 끝 알림이 restTimer 를 맞추는 방식(core/restalarm.js)과 같다.

버튼을 누르면 네이티브 리시버가 앱 전용 저장소의 기록장에 세션 id, 운동 uid, 세트 번호, 누른 시각을 적는다.
이어서 알림을 다음 세트와 새 카운트다운으로 바꾸고 휴식 끝 알람을 예약한다. 웹뷰는 깨우지 않는다.

앱이 다시 열리면, 또는 앱이 떠 있는 동안 버튼을 누르면 웹 코드가 기록장을 읽어 한 번의 커밋 안에서
toggleSetDone 을 누른 시각으로 차례로 적용한다. 이미 완료된 세트, 사라진 세트, 다른 세션의 기록은 건너뛰고 몇 개를 건너뛰었는지 알린다.
마지막으로 적용한 기록 번호를 같은 커밋에서 세션에 적어 두므로, 앱이 도중에 꺼져도 두 번 적용되지 않는다.
그 뒤 웹 코드가 네이티브에 그 번호까지 지우라고 알린다.

무게 찾기 중인 운동은 방금 세트의 느낌(가벼움, 적당, 무거움)에 따라 다음 무게가 바뀐다. 그때 알림은 버튼 없이
앱에서 느낌을 골라 달라고만 하고, 누르면 앱이 열린다. 톱세트의 남은 반복과 운동 끝 느낌은 다음 세트 무게를 바꾸지 않으므로
앱을 열었을 때 지금처럼 카드에서 고르면 된다.

쓰지 않는 방법도 적어 둔다. 포그라운드 서비스로 앱을 살려 두는 방법은 쓰지 않는다. 앱 프로세스를 살려 두어도 잠긴 동안
웹뷰가 자바스크립트를 처리한다는 보장이 없고(11/14 관찰), 안드로이드 14부터는 서비스 유형과 그 권한을 밝혀야 하며 배터리를 계속 쓴다.
카운트다운은 시스템이 그리고 버튼과 알람은 브로드캐스트로 오므로 서비스 없이 된다. 네이티브가 웹 저장소의 기록을 직접 고치는 방법도 쓰지 않는다.
상태 변경을 전이 함수로만 한다는 원칙을 깨고, 저장 형식이 바뀔 때마다 APK 를 고쳐야 한다. 미디어 알림(MediaStyle)도 쓰지 않는다.
미디어 세션을 흉내 내야 하는데, 운동 중에 음악 앱을 틀면 잠금 화면의 같은 자리를 두고 다투고 이어폰 버튼 입력이 우리 앱으로 올 수 있다.

### 4. 알림에 보일 내용

| 때 | 제목 | 본문 | 시간 표시 | 버튼 |
| --- | --- | --- | --- | --- |
| 휴식 중 | 휴식 중 | 다음: 크런치 2세트, 17회 | 남은 시간 카운트다운 | 세트 완료 |
| 휴식이 끝난 뒤 | 휴식이 끝났어요 (진동과 소리 한 번) | 다음: 크런치 2세트, 17회 | 끝난 뒤 지난 시간 | 세트 완료 |
| 휴식이 없을 때 (시작 직후, 건너뛰기 뒤) | 다음 세트 | 벤치프레스 1세트, 60kg × 8회 | 없음 | 세트 완료 |
| 무게 찾기 느낌이 필요할 때 | 앱에서 느낌을 골라 주세요 | 방금 세트의 느낌으로 다음 무게를 정합니다 | 없음 | 없음 (누르면 앱) |
| 마지막 세트 뒤 | 마지막 세트까지 끝났어요 | 앱에서 저장하고 종료하세요 | 없음 | 없음 (누르면 앱) |

알림은 세션을 시작하면(첫 세트를 체크하거나 '시작'을 누르면) 생기고, 저장하거나 버리면 사라진다. 세션을 만들기만 한 시작 전 화면에서는 띄우지 않는다.
앱이 화면에 떠 있을 때도 음악 앱처럼 그대로 둔다. 알림 본문을 누르면 앱이 열린다. 휴식 끝의 진동과 소리는 지금의 '휴식 끝' 채널을 그대로 쓴다.

라이브 업데이트 승격도 함께 요청한다. 삼성이 받아 주면 상태 바 칩과 나우 바에 남은 시간이 뜨고, 받아 주지 않아도 보통 알림으로는 똑같이 동작한다.

### 5. 순서와 검증

APK 에 새 플러그인을 넣어 먼저 폰에 덮어 설치하고, 그 뒤 웹 코드를 push 한다. 웹 코드는 플러그인이 있는지 보고 쓰고,
없으면 지금의 휴식 끝 알림으로 돌아간다(known-issues 49). 단위 테스트는 알림 계획 계산(전이 함수를 거친 순서, 톱세트 뒤 백오프 무게)과
기록 다시 적용(누른 시각, 두 번 적용 방지, 건너뛰기)을 본다. E2E 는 브리지를 흉내 내어 계획이 넘어가는 때와 앱 복귀 때 기록이 들어가는지 본다.
폰에서는 잠금 화면에서 알림 버튼으로 세트를 둘 넘기고, 휴식 끝 진동이 제때 오는지 scripts/measure-notice.mjs 로 재고,
앱을 열어 기록과 세트 간격이 맞는지 본다. 나우 바와 상태 바 칩에 뜨는지, 잠금 화면에 알림 내용과 버튼이 보이려면 휴대전화 설정을 무엇으로 두어야 하는지도 확인해 NATIVE_APP.md 에 적는다.
