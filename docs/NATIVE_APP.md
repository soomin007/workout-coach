# 안드로이드 앱 (Capacitor)

크롬에서 쓰던 PWA 를 Capacitor 로 감싼 안드로이드 앱이다. 앱으로 감싼 이유는 휴식 끝 알림이다. 크롬은 화면이 꺼지거나
다른 앱으로 넘어가면 페이지의 타이머를 멈추고, 진동 API 도 보이지 않는 화면에서는 동작하지 않는다. 정해진 시각에 알림을 띄우는
웹 API(Notification Triggers)는 시험 단계에서 접혔다. TWA(Bubblewrap)는 알림을 웹 API 에 기대므로 같은 한계가 있어서,
안드로이드 알람을 직접 쓸 수 있는 Capacitor 를 골랐다(2026-11-14). 휴식 끝과 운동 날 알림은 모두 폰 안에서 정해지는 일이라
서버 푸시(FCM)는 쓰지 않는다.

버전: `@capacitor/core`, `cli`, `android` 8.6.0, `@capacitor/local-notifications` 8.3.1, `@capacitor/app` 8.1.2.
모두 나온 지 2주가 지난 버전으로 골라 package.json 에 고정했다(8.6.1 과 8.6.2 는 설치 이틀 전에 나왔다).

## 웹 화면은 GitHub Pages 에서 받는다

앱은 `capacitor.config.json` 의 `server.url` 로 https://soomin007.github.io/workout-coach/ 를 띄운다. 그래서 main 에 push 하면
크롬 PWA 와 앱이 함께 바뀌고, APK 는 네이티브 쪽(매니페스트, 플러그인, 아이콘, `native/web`)을 바꿀 때만 다시 빌드한다.
이 방식은 사용자가 2026-11-14 에 골랐다. `app/` 은 지금처럼 빌드 없는 ES 모듈로 두고, `@capacitor/core` 를 들이지 않는다.
앱이 페이지에 넣어 주는 `window.Capacitor` 브리지의 `nativePromise` 로 플러그인을 직접 부른다.

Capacitor 문서는 `server.url` 을 라이브 리로드용이라고 한다. 그 이유를 하나씩 따져 보면, 스토어 심사 문제는 Play 스토어에 올리지 않는
개인용 앱이라 해당하지 않는다. 원격 코드가 네이티브 기능을 쓴다는 점은, 브리지가 이 앱의 출처(https://soomin007.github.io)에만 들어가고
APK 에 든 플러그인이 알림과 뒤로 가기 처리뿐이라 위험이 작다. 실제로 남는 문제는 웹 코드와 APK 의 버전이 어긋나는 것이다.
그래서 웹 코드는 네이티브 기능을 부르기 전에 그 APK 에 플러그인이 있는지 확인하고(`ui/native.js` 의 `hasPlugin`),
플러그인을 새로 들일 때는 APK 를 먼저 폰에 설치한 뒤 그 플러그인을 쓰는 웹 코드를 push 한다(known-issues 49).

서비스 워커와 오프라인 동작은 Capacitor 8.6.0 소스(Bridge.java 의 `loadWebView`)로 확인했다. 웹뷰가 DOCUMENT_START_SCRIPT 기능을
지원하면 Capacitor 는 브리지 스크립트를 `addDocumentStartJavaScript` 로 그 출처의 모든 문서에 넣는다. 서비스 워커가 캐시에서 준 화면에도
브리지가 붙으므로, 인터넷이 없을 때도 알림을 예약할 수 있다. 이 기능이 없는 아주 오래된 웹뷰에서는 HTML 응답에 스크립트를 끼워 넣는
방식으로 물러나는데, 이때는 캐시에서 온 화면에 브리지가 없어 알림이 동작하지 않는다. 안드로이드 시스템 웹뷰는 Play 스토어로 자동
업데이트되므로 만날 일이 드물고, 만나면 설정 탭에 '휴식 끝 알림' 카드가 보이지 않는 것으로 알 수 있다.

앱을 처음 열 때는 인터넷이 있어야 한다. 아직 서비스 워커가 없기 때문이다. 이때 연결이 없으면 APK 안에 든 `native/web/offline.html` 이
대신 뜬다(`server.errorPath`). 한 번 열고 나면 지금 PWA 처럼 서비스 워커가 화면을 준다. 업데이트도 PWA 와 같아서 앱을 열거나 앱으로
돌아올 때 새 버전을 받고, 설정 탭에 버전이 보인다(known-issues 8). 서비스 워커 SHELL 에서 파일이 빠지면 앱이 오프라인에서 아예 뜨지
않으므로 `tests/unit/sw_shell.test.js` 가 app/js 의 모든 파일이 SHELL 에 있는지 검사한다.

앱 웹뷰의 저장소는 크롬과 출처가 같아도 따로다. 처음 설치하면 기록이 비어 있으므로, 설정 탭의 기록 동기화에서 GitHub 에 연결해
data.json 을 받는다. 저장소 이름은 미리 채워져 있고 토큰만 직접 붙여 넣으면 된다. 앱을 지우면 앱 안의 기록도 지워지고,
덮어 설치하면(업데이트) 그대로 남는다. 뒤로 가기는 `@capacitor/app` 이 웹뷰의 방문 기록으로 넘겨 크롬과 같은 가드(known-issues 7)가 동작한다.
이 플러그인이 없으면 뒤로 가기 한 번에 앱이 닫힌다.

## 무엇을 커밋하나

| 경로 | 커밋 | 내용 |
| --- | --- | --- |
| `capacitor.config.json` | 한다 | 앱 id, 이름, server.url, 오프라인 페이지, 알림 아이콘 |
| `android/` | 한다 | Capacitor 가 만든 안드로이드 프로젝트. 매니페스트 권한, 아이콘, 시작 화면을 고쳐 두었다 |
| `native/web/` | 한다 | APK 에 들어가는 웹 파일(오프라인 안내와 빈 index.html) |
| `scripts/android.mjs`, `scripts/measure-notice.mjs` | 한다 | 빌드와 설치, 알림 지연 실측 |
| `android/app/build/`, `*.apk` | 안 한다 | 빌드 산출물. 공개 저장소에 바이너리가 쌓이고 소스에서 다시 만들 수 있다 |
| `android/local.properties` | 안 한다 | PC 마다 다른 SDK 경로. 빌드 스크립트가 없으면 만든다 |
| `android/app/src/main/assets/public`, `assets/capacitor.*.json` | 안 한다 | `cap sync` 가 매번 복사해 넣는 사본 |

무엇을 빼는지는 Capacitor 가 만든 `android/.gitignore` 가 정한다. 디버그 APK 는 이 PC 의 `C:\Users\soomi\.android\debug.keystore` 로
서명된다. 다른 PC 에서 빌드하거나 이 파일이 없어지면 서명이 달라 덮어 설치가 되지 않고, 앱을 지웠다 다시 깔아야 한다(기록은 동기화로 다시 받는다).
이 파일을 백업해 두거나 빌드는 이 PC 에서만 한다.

## 휴식 끝 알림

세트를 체크해 휴식 타이머가 시작되면 앱은 끝 시각에 알림을 예약한다. 알림은 중요도 높은 '휴식 끝' 채널로 와서 화면 위에 뜨고(헤즈업)
진동과 기본 알림음을 낸다. 본문에는 다음 세트가 "다음: 바이셉스 컬 2세트, 10kg × 12회"처럼 적힌다. −15 와 +30 을 누르면 새 끝 시각으로
다시 예약하고, 다음 세트를 체크하면 새 휴식으로 바꾼다. 건너뛰기, 세트 체크 해제, 세션 종료와 버리기는 예약과 알림 창에 남은 알림을 지운다.

구현은 두 층이다. `core/restalarm.js` 가 세션의 restTimer 에서 "지금 예약돼 있어야 할 알림"을 계산하고, `ui/native.js` 가 렌더마다
그 결과를 마지막으로 맞춘 상태와 비교해 바뀐 때만 플러그인을 부른다. 상태 변경은 지금처럼 `session.js` 전이 함수로만 하고 알림은
그 결과를 따라가므로, 휴식을 바꾸는 동작마다 예약 코드를 붙이지 않았다. 휴식을 바꾸는 새 동작이 생겨도 알림이 저절로 맞는다.
시간이 흐르는 것만으로는 아무것도 바꾸지 않아서 휴식이 끝나는 순간 알림을 지워 버리는 일도 없다. 앱이 꺼졌다 다시 뜨면 남은 휴식으로
다시 예약한다.

앱이 화면에 떠 있을 때도 알림은 온다. 그래서 앱에서는 크롬처럼 화면 안에서 따로 진동하지 않는다(진동이 두 번 겹치므로).
알림 권한을 꺼 두면 예약하지 않고 화면 안 진동으로 돌아간다. 크롬에서는 브리지가 없어 지금처럼 진동만 한다.

권한은 둘이다. 알림 권한(POST_NOTIFICATIONS, 안드로이드 13 이상)은 앱을 시작할 때 한 번 묻는다. 묻지 않으면 첫 세트를 체크할 때
플러그인이 그 자리에서 물어 운동이 끊긴다. 정확한 시각 알람은 매니페스트의 USE_EXACT_ALARM 이 설치할 때 허용한다.
플러그인이 넣는 SCHEDULE_EXACT_ALARM 은 안드로이드 14 부터 새로 설치한 앱에 꺼진 채로 주어지고, 꺼져 있으면 플러그인이 운동 중에
설정 화면을 연다. 둘 중 하나가 꺼져 있으면 설정 탭의 '휴식 끝 알림' 카드에 이유가 보인다. 같은 카드의 '시험 알림 (10초 뒤)' 로
화면을 끈 채 울리는지 직접 볼 수 있다. 플러그인 기본 옵션의 함정은 known-issues 47 에 있다.

## 빌드와 설치

Android Studio 없이 명령줄 도구만 쓴다. 2026-11-14 에 아래를 설치했다. 시스템 PATH 와 JAVA_HOME(JDK 17, Godot 안드로이드 내보내기용)은
바꾸지 않았고, 빌드 스크립트가 띄우는 Gradle 에만 JDK 21 을 넘긴다.

- JDK 21: `C:\Users\soomi\Android\jdk-21.0.13+9` (Temurin 21.0.13, 압축 파일을 푼 것)
- Android SDK: `C:\Users\soomi\Android\sdk` (cmdline-tools 23.0, platform-tools 37.0.1, platforms;android-36, 빌드 도구는 Gradle 이 받는다)
- 받은 압축 파일: `C:\Users\soomi\Android\_downloads` (체크섬 확인 뒤 남겨 둠, 지워도 된다)

명령은 셋이다. 웹 화면(app/)만 고쳤으면 빌드할 필요 없이 push 만 한다.

```bash
npm run android:build
```

```bash
npm run android:install
```

```bash
npm run android:run
```

`android:build` 는 `cap sync android` 뒤 디버그 APK(`android/app/build/outputs/apk/debug/app-debug.apk`)를 만들고,
`android:install` 은 USB 로 연결한 폰에 덮어 설치하며, `android:run` 은 둘을 하고 앱을 띄운다.
폰은 설정 > 휴대전화 정보 > 소프트웨어 정보에서 빌드번호를 일곱 번 눌러 개발자 옵션을 켜고, 개발자 옵션에서 USB 디버깅을 켠 뒤
PC 에 연결해 "USB 디버깅 허용"을 누른다(삼성 기준).

## 실측: 화면을 끈 채 알림이 늦는 시간

2026-11-14 사용자 폰(갤럭시 S22+ SM-S906N, 안드로이드 16, 시스템 웹뷰 157)에서 쟀다. 앱과 같은 옵션(allowWhileIdle, 정확한 알람)으로
시험 알림을 예약하고 곧바로 adb 로 화면을 껐다. USB 로 연결돼 충전 중이면 절전이 걸리지 않으므로, 측정하는 동안만 `dumpsys battery unplug` 로
배터리 상태를 흉내 내고 끝나면 되돌렸다. 늦은 시간은 안드로이드 이벤트 로그의 `notification_enqueue`(알림을 올린 때)와
`notification_alert`(진동과 소리를 낸 때)를 예약 시각과 비교한 값이다.

| 휴식 | 조건 | 알림이 뜬 때 | 진동과 소리 |
| --- | --- | --- | --- |
| 15초 | 화면 끔 | +0.12초 | +0.37초 |
| 60초 | 화면 끔 | +0.04초 | +0.27초 |
| 120초 | 화면 끔 | +0.04초 | +0.26초 |
| 180초 | 화면 끔 | +0.04초 | +0.26초 |
| 60초 | 화면 끔, Doze 강제(`dumpsys deviceidle force-idle`) | +0.05초 | +0.27초 |
| 180초 | 실제 흐름: 세션을 만들고 풀업 첫 세트 체크 뒤 화면 끔 | +0.03초 | +0.24초 |

예약 알림만으로 제때 울린다. 잠금 화면 카운트다운(포그라운드 서비스)은 알림이 늦을 때를 대비해 검토했던 것이라 지금은 필요 없다.
다만 측정은 이 앱을 막 쓰던 상태에서 했다. 삼성은 며칠 쓰지 않은 앱을 '절전 앱'으로 돌리므로, 오랜만에 운동하는 날 알림이 늦으면
설정 > 배터리 > 백그라운드 사용 제한에서 이 앱이 절전 목록에 들어갔는지 먼저 본다.

다시 잴 때는 폰을 USB 디버깅으로 연결하고 앱을 화면에 띄운 뒤 아래 명령을 쓴다. `--idle` 을 붙이면 Doze 를 강제로 건다.
화면을 오래 끈 뒤 잠금 화면이 떠 있으면 앱 웹뷰가 멈춰 명령이 끝나지 않으므로, 스크립트가 잠금을 풀어 달라고 알린다(known-issues 50).

```bash
node scripts/measure-notice.mjs 60 120 180
```

## 남은 결정

- 잠금 화면 카운트다운(포그라운드 서비스, 예: `@capawesome-team/capacitor-android-foreground-service`)은 실측에서 알림이 0.05초 안에
  울려 지금은 넣지 않는다. 잠금 화면에서 남은 시간을 보고 싶어지면 그때 다시 정한다.
- 알림에 '세트 완료' 같은 버튼을 넣을지는 써 본 뒤 정한다. 지금은 넣지 않았다.
- 앱이 화면에 떠 있을 때도 알림이 뜬다. '화면 유지'를 켠 채 폰을 벤치에 두어도 소리로 알 수 있게 그렇게 두었다.
  거슬리면 화면이 보이는 동안에는 예약하지 않고 화면 안 진동만 하도록 바꿀 수 있다(화면이 가려질 때 예약).
- 크롬 PWA 를 계속 둘지 정한다. 홈 화면에서 지우기 전에 PWA 쪽 기록이 GitHub 에 올라갔는지 먼저 확인한다.
- 디버그 서명 키 대신 이 앱 전용 서명 키를 만들지 정한다(위 '무엇을 커밋하나' 의 서명 이야기).
- 동기화 연결 옮기기 QR 을 폰 카메라로 찍으면 크롬이 열리고 앱으로 오지 않는다. 앱에서는 토큰을 직접 붙여 넣는다.
  앱으로 바로 열리게 하려면 App Links(soomin007.github.io 에 assetlinks.json)가 필요하다.
